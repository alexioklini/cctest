Final: engineer 0.97 vs polish 0.67 overall, actionability +0.22, zero drift regressions. **eval/refine_eval.py build_new() IS the spec the handler implements — keep in sync.** Suite: refine_eval.py + refine_cases.json + refine_rubric.md + refine_live_check.py (live-endpoint parity). **v9.82.2 (2026-06-06) — OVER-STRICTNESS follow-up fix.** Reported as a "web-fetch bug" (weather chat retrieved sites but refused to answer). Diagnosis chain: NOT the fetch plumbing — the casual prompt "wie wird das wetter morgen in wien" had been run through **Engineer**, which rewrote it to "Gib eine präzise Wettervorhersage … aus". The injected "präzise" (+ model reaching for "offizielle Quelle") RAISED the agent's evidentiary bar → auto-router tagged it 'research' → agent guessed authoritative forecast URLs (all 404) instead of fetching the gmx.at/vienna.at links search returned → refused. **The identical RAW prompt in a sibling chat fetched vienna.at and answered perfectly** — proving plumbing fine, refined wording broke it. This is a THIRD failure mode the v9.82.1 eval never covered: not fabrication (no false fact), not bloat (refined prompt was SHORT) — **OVER-STRICTNESS**. Fix = Engineer-prompt rule: casual everyday web-lookups (weather/FX/score/hours/'what is X') stay casual, fix spelling+stop, never inject precision/officialness words or rigid output spec. Eval-first: added `mode:casual_lookup` cases CHAT8 (exact German weather draft) + CHAT9 (EUR/USD), rubric section, + absolute `over_strict_casual` hard gate in harness. Baseline reproduced bug verbatim (DRIFT/0.00); post-fix 1.00. **CRITICAL eval detail: refine endpoint uses `mistral-small-latest` (tools_config.json refinement.model), NOT the medium default — run `--refine-model CLIProxyAPI/mistral-small-latest` or you won't reproduce.** SCHED1/2 drift intermittently on small (pre-existing variance, neutral across 4 reruns, NOT a regression — don't chase).
