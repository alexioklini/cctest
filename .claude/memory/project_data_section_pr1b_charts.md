**Shipped 2026-05-12** (PR1b, on PR1/PR2/PR3 — see `project_data_section_pr1_phase_a_skeleton.md` etc.). Completes the chart half of the original Phase A. Charts were deliberately split out of PR1 because §16/§17 didn't depend on them.

**What landed (files):**
- `engine/tools/data_viz.py` — `tool_data_render_chart(args)`: `{spec, table, scale?}` → `{ok, table, spec, png_b64, n_rows}`. Validates the table exists; collects every encoded `field` from the spec (walks layer/concat/facet) and checks each is a column of the bound table (skipped if the spec uses `calculate`/`aggregate`/`fold`/`window`/`joinaggregate` — Vega validates those on render); pulls a ≤5000-row sample of the table, inlines it as `data.values` (the spec passed by the caller must NOT have a `data` key), renders a PNG via `vl_convert.vegalite_to_png` (scale default 2.0); raises (returns `{error}`) on an invalid spec / missing column so the agentic loop hands the error back. Saves the PNG as a `chart_N.png` artifact (via `brain._after_file_write`), emits a `data_chart` SSE event if `event_callback` is set, audits `data_render_chart`. Helpers: `_collect_encoded_fields`, `_spec_uses_calculate_or_aggregate`.
- `engine/tools/data_viz_prompts.py` — rewrote `DATA_WORKBENCH_PROMPT`: the chart-call requirement is now a `>>> CHARTS — READ THIS FIRST <<<` block at the TOP (models weight early instructions higher), with a concrete 4-step recipe (`data_query`+`register_as` to build the aggregated table → `data_render_chart` with a no-`data`-key spec → tool renders → describe, don't paste the spec) and explicit "there is no `plot` tool / no matplotlib / a ```vega or ```python code block produces nothing / don't hand-type data values". Plus a Vega-Lite cheat-sheet (bar/stacked/grouped/line/scatter/histogram/pie templates, DuckDB-type→Vega-type mapping). NOT a verbatim Data-Formulator copy.
- `brain.py` — registered `data_render_chart` (4 sites; `data_viz` group now `{data_query, data_anonymise, data_scan_files, data_render_chart}`). **Also: added `data_query` to `_DEDUP_EXEMPT`** — it's read-only and legitimately called repeatedly with the same SQL during workbench exploration (SHOW TABLES / DESCRIBE / re-running a probe); the bare-string dedup was aborting the turn at the 2nd dup before the model could chart.
- `handlers/data_viz.py` — `POST /v1/data/sessions/<sid>/render` (no-LLM re-render of an edited Vega-Lite spec — same body as the tool; primes/clears the workbench thread-locals like the other endpoints).
- `server.py` — route for `…/render` (POST).
- `web/index.html` — eager `<script src="…/vega@5">`/`vega-lite@5`/`vega-embed@6` CDN tags; a "Chart builder (Vega-Lite)" pane in the Data view's right column (`dv-right-col` wraps the chat-CTA + the chart pane): table picker, bar/line/scatter template buttons, editable spec textarea, "Preview (client)" via `vegaEmbed` over the ≤20-row sample, "Render PNG (server)" via `/render` → shows the PNG inline.
- `web/css/main.css` — `.dv-right-col`, `.dv-chart-pane`, `.dv-chart-spec` (monospace textarea), `.dv-chart-out img` (white bg).
- `web/js/data.js` — `dvSyncChartTableSelect` (called from `dvRenderTables`), `dvChartCols`, `dvChartInsertTemplate(bar|line|scatter)` (guesses nominal/quantitative/temporal columns from DuckDB types), `dvChartPreview` (client vega-embed over the cached sample), `dvChartRenderServer` (`/render`).
- `eval/data/` — `fixture.csv` (15-row synthetic risk register: entity/tier/status/findings_open/closed/opened_month/region), `questions.json` (10 prompts: 5 chart asks `C1–C5`, 3 follow-ups `F1–F3` with `context_after`, 2 deliberate ambiguities `A1/A2`), `run.py` (login → fresh workbench per Q → upload fixture → [set up context turn] → chat turn → parse SSE for `data_render_chart` tool call → deterministic scorer: mark in `expect.mark_in` + every required raw `field` present (accepts renamed aggregate columns via dimension-token substring match) + ambiguity Qs pass when NO chart call + the model clarifies), `README.md`.
- `CLAUDE.md` — Data Workbench section extended with `data_render_chart` + `/render` + the canary + the dep note.

**Deps:** `pip install --break-system-packages vl-convert-python` (1.9.0 — a self-contained Rust wheel; `vegalite_to_png`/`vega_to_png`/`svg_to_png`; no node/headless browser). `jsonschema` already present but unused (vl-convert validates on render).

**Eval result (2026-05-12, Mistral/mistral-medium-3.5):** ~0.45 mean across 10 questions, run-to-run variant (different chart Qs pass/fail each run). **The pipeline works** — `data_render_chart` renders correctly every time it's *called* (C1/C4/F3 pass consistently; the `/render` endpoint and the web pane both verified rendering PNGs + surfacing bad-spec errors). The failures are all "no `data_render_chart` call" — Mistral Medium's default reflex on a chart ask is to **emit a ```vega / ```python / matplotlib code block in its reply** (sometimes hallucinating a `plot` Plotly-style tool) instead of calling the tool. The TOP-of-prompt rewrite + the `data_query` dedup fix lifted it from ~0.32 to ~0.45 but didn't fully fix it. This is the exact risk the plan's risk table flagged ("if a model is hopeless at Vega-Lite that's a per-model config choice, not a redesign") — a stronger model or a fine-tuned per-model nudge would do better; it's a tuning decision, not part of PR1b. The canary is now the regression baseline — re-run before/after any change to `data_render_chart`, the chart cheat-sheet, or the workbench prompt.
