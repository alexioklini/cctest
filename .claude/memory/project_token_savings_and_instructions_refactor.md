Three coordinated changes to cut token consumption and make discipline behavior owner-editable.

**1) Per-session read_document / read_file cache (A1+)** — `_read_doc_cache` in claude_cli.py keyed by `(session_id, abs_path)` with `(mtime, size, turn, content_hash)` value. On a second full-shape read in the same session, a cache hit returns a stub `{"cached": true, "first_read_in_turn": N, "content_hash": "...", "note": "Bereits in Turn N ..."}` instead of streaming the full file content back into the model's context. Pagination args (`offset`/`limit`/`pages`/`sheet`/`slides`, plus any explicit `limit` on read_file) bypass the cache entirely. `_after_file_write` invalidates the cached entry so a write+read sequence in the same chat always sees fresh content. read_document and read_file are added to `_DEDUP_EXEMPT` so the bare-string dedup doesn't kill the second read; cache is the smarter dedup. `_thread_local.tool_round` is set in `_execute_tools_batch` so the stub names the right turn. TTL 1h, max 64 entries per session.

**2) Project preamble (B1)** — dynamic project state (drawer count, attachment count, input-folder list with absolute paths, path-join example) moved out of `_build_system_prompt` into a per-session preamble injected on the first user message at round 0, sibling to the user-greeting + auto-maintained-profile preambles. New helper `_project_preamble_text(agent_id, project_name)` builds it. The injection block was hoisted out of the `if _greeting_uid:` guard so anonymous (auth-off) sessions in projects also get the absolute paths. KV-cache stability win: system prompt stays project-agnostic in shape; the per-project string only lives in the user message.

**3) Disciplines → project Instructions (#3)** — REFUSAL + PRECISION + CITATION discipline blocks (the v8.22.0 anti-hallucination rules) moved out of `_build_system_prompt`'s static text into a new module-level `DEFAULT_PROJECT_INSTRUCTIONS` constant (4081 chars). Used as the **fallback** when `project.json.instructions` is empty — so every project still gets the disciplines for free with no migration. Project owners can replace the default by writing their own text in the right-pane Instructions editor; override REPLACES the default rather than appending (an owner can opt out of the citation requirement by writing simpler instructions). New endpoint `GET /v1/projects/default-instructions` returns the constant; the editor modal grows a "Load default" button that pre-fills the textarea so owners can start from the disciplines and customise. Brain mechanics (the 3-step retrieval flow, `read_path` vs `read_path_original`, binary→.md companion explanation, KG hint block) stay in the system prompt — those are infrastructure facts, not editable behavior.

**Why:** A1+ was the largest hands-on token saving (multi-turn re-reads of the same .md companion in policy chats). B1 is mostly cosmetic for KV-cached providers but real for Mistral API and other no-cache cloud providers + first-turn cost on every new project chat. Disciplines-as-Instructions is the architectural fix the user requested — different projects need different discipline thresholds (a brainstorming project doesn't want REFUSAL DISCIPLINE; a marketing project may not need verbatim citations).

**How to apply:**
- When debugging "model re-reads file every turn" → look at `_read_doc_cache_lookup` first; the stub shape carries `first_read_in_turn` and `content_hash` so you can tell which turn first read it.
- When the model writes a file then reads it back → the cache invalidates correctly via `_after_file_write` → `_read_doc_cache_invalidate(path)`.
- When a project owner asks "how do I change Brain's refusal/citation behavior" → point them at the right-pane Instructions editor; the "Load default" button is the entry point.
- When `_build_system_prompt` is called for a project chat with empty `project.json.instructions` → the default text appears in the prompt under the label "PROJECT INSTRUCTIONS (Brain default; the project owner can replace these by editing the project's Instructions field):". When non-empty, label is "PROJECT INSTRUCTIONS (set by the user for this project):".
- CLAUDE.md's v8.22.0 section talks about REFUSAL/PRECISION/CITATION living in `_build_system_prompt`'s PROJECT MEMORY scope. After this refactor that's no longer true — the disciplines live in `DEFAULT_PROJECT_INSTRUCTIONS` (module-level constant) and surface via the project Instructions injection. CLAUDE.md needs an update if the user revises it.
