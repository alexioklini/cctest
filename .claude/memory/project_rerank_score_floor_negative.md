2026-05-27: Implemented + eval'd the rerank score-floor follow-up flagged in [[project_reranker_enabled_2026_05_27]] (refuse when the top cross-encoder score is below a threshold, to claw back the F1/F2 refusal regression the reranker introduced). **NEGATIVE — reverted both code and config.**

**Design:** after the rerank pass in `engine/mempalace_glue.py`, if the reranker actually scored a pool (not skip-gated by ≥0.20 filename boost) AND `config → mempalace.reranker.score_floor` is set, compare `sigmoid(top_logit)` against the floor (a 0-1 probability; bge-reranker-v2-m3 emits raw logits). Below floor → return `_ok` with empty drawers + `below_score_floor:True` + a "not in the sources, do not fabricate" read_hint. Default-off (no-op without the config key).

**Why it failed — the discriminating signal isn't there.** An isolated probe (rerank the raw top-40 vector hits) suggested clean separation: in-corpus content questions 0.64-0.73, out-of-corpus F-bucket ~0.50. BUT the **real pipeline** (filename-boost + widen + substitute before rerank) collapsed that margin. Measured top_prob in the actual run at floor=0.52: F1=0.52, F3=0.51, **C2=0.50, F2=0.50**. So a genuine in-corpus question (C2 "Bildschirmsperre/Verhalten am Arbeitsplatz") scored at/below the out-of-corpus money-laundering question. **No floor value catches F1 but spares C2** — they're inseparable by absolute rerank score on this corpus.

**Eval (15Q, mistral-medium-3.5, disc=none, mistral judge, reused reranker-on gold):** brain **0.73 vs 0.80 baseline = −0.07**. Floor fired on F1/F2/F3 (correct targets) AND C2 (wrong). Net per-question: F1 0.27→0.70 (+0.43, the one real win), C2 0.65→0.33 (−0.32), and it *hurt* F2 0.93→0.75 / F3 0.85→0.83 — F2/F3 already refused gracefully WITH verbatim "evidence-of-absence" citations at baseline; the floor's bare empty-result refusal loses those citation points. (P2/P3/M3 also dropped but did NOT trip the floor → Mistral judge variance, ±0.09 mean per [[project_eval_citation_validator_phase1]].)

**Lesson:** the reranker's value is *re-ordering* (which it does well, +0.08), not *absolute relevance calibration*. The F1 fabrication is a real failure but it's only ONE question; fixing it via a score-floor costs more than it buys because (a) it false-positives on weak-in-corpus questions and (b) it degrades the already-good F2/F3 refusals. Adds to the list of levers that don't beat reranker-on 0.80 (see [[project_contextual_retrieval]], [[project_doc_refinement_eval]]). Run dir: `eval/results/20260527T203736_disc-none_score-floor-052`.

**SECOND + THIRD attempts (2026-05-27, same session) — also NEGATIVE, lever abandoned.**

*Probe-driven detour, two of my own errors corrected along the way:*
- An offline rank-probe (rerank raw top-40 vector hits, score the rank of the Opus-cited correct doc) showed **bge beats BM25 and Qwen3-Reranker-0.6B on within-corpus ranking** (bge gets P2/C3/R3/P1 to rank 1-7; BM25 leaves C3 at rank 15; Qwen ties bge). **BM25 is too weak standalone**; only useful as a fusion channel — not worth the dep + German tokenization.
- **DOUBLE-SIGMOID BUG found:** bge-reranker-v2-m3's `CrossEncoder` in sentence-transformers 5.4.1 has `activation_fn=Sigmoid()`, so `.predict()` ALREADY returns a 0-1 probability (NOT a raw logit). The original floor code (attempt 1) applied `1/(1+exp(-x))` on top, squashing every score toward 0.5 — that's why attempt-1 saw the meaningless F1=0.52/C2=0.50 cluster. **Do not sigmoid bge predict output.** (Qwen DOES return logits → needs one sigmoid; its full-15Q in/out separation OVERLAPS −0.16 because weak-in-corpus R2=0.068 < out-of-corpus F1=0.22 — Qwen is NOT the fix either.)
- Re-probed with correct per-model score handling: **bge probabilities DO separate offline** — F-bucket ≤0.007, in-corpus min 0.014 (R2). So attempt 3: fixed floor (read bge prob directly, no sigmoid), `score_floor=0.010`.

*Eval attempt 3 (15Q, mistral-medium, mistral judge, reused gold, dir `20260527T210239_disc-none_score-floor-010-fixed`):* brain **0.80 — exact wash vs baseline, NOT a win.** And it failed for the SAME root reason: **the offline probe pool ≠ the live reranked pool.** The live pipeline reranks the filename-boosted/widened/substituted pool, which scores differently. In the live run: **F1's top live passage scored ABOVE 0.010 → floor never fired → F1 still fabricated (0.25).** C2's top live passage scored 0.008 → floor FIRED on the (in-corpus!) question. C2 didn't crash this time only by luck: the model re-queried `mempalace_query` with different phrasing, cleared the floor on attempt 2, and recovered to 0.97 — an accidental "try-harder" side effect, not the floor's design, and pure variance. So the 0.80 mean = accidental C2 gain canceling the unchanged F1 loss.

**FINAL VERDICT — abandon the rerank score-floor.** Across three attempts the immovable fact is: **in the LIVE pipeline (not the offline probe), the out-of-corpus F1 top passage scores ≥ a genuine in-corpus question's top passage** (attempt1: F1 0.52 ≥ C2 0.50; attempt3: F1 >0.010 > C2 0.008). No threshold catches F1 without firing on a valid question. The offline probe is NOT representative — always measure on the live `tool_mempalace_query` path, not a standalone rerank of raw vector hits. **For F1 fabrication specifically, the only untried lever left is model-side: a per-claim citation-grounding gate that forces refusal when the model can't quote a real source — attacks fabrication directly, no retrieval-score guess.** A stronger reranker (Qwen) does NOT give a usable margin and is not worth the size/speed cost.
