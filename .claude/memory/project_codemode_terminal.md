**DECISIONS (user):** real interactive PTY (not command-by-command) + pragmatic cwd-lockdown (not hard sandbox).

**TRANSPORT (key recon finding):** server is ThreadingHTTPServer = NO WebSocket support. SSE is the established streaming pattern (server_lib/sse_stream.py, chat stream). So terminal = SSE for output + POST for input (NOT WebSocket). Auth = Bearer header (SSE inherits it; WS couldn't set headers from browser JS → another reason for SSE).
