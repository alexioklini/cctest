2026-06-22 (v9.189.1→9.189.2, project risikoanalysen): user reported "every sync re-runs KG extraction although nothing changed", then "why mining", then "why indexing took 2 min". Three distinct things, diagnosed via kg_extraction_log / kg_extraction_progress / project_sync_runs.summary.

**1. KG re-extracted everything every cycle — ROOT CAUSE = volatile cursor key.** `kg_extraction_log` showed drawers_processed=412(NRA)/34(aml), drawers_skipped=0 every run, fluctuating triples. The KG progress cursor key (engine/kg_extract.py source_file chunking mode) was `<representative_drawer_id>#<chunk>`. `representative_drawer_id = drawer_ids[0]` where drawer_ids came from Qdrant `col.get(where=wing)` in NON-deterministic order (`_iter_wing_source_files`). Drawer ids ALSO churn across mining cycles (miner re-files with content-hash ids; many drawers/source). So the cursor key drifted → `_already` skip-set never matched → full re-extract. Evidence: 178→343 distinct rep_did prefixes across 412→793 progress rows for ONE source. FIX v9.189.1 = `sorted(drawer_ids)` (necessary, NOT sufficient — sorting a changed id-set still moves [0]). FIX v9.189.2 (the real one) = cursor key now `src_<sha1(source_file)[:24]>#<chunk>` from the SOURCE FILE PATH (constant across cycles). rep_did kept for triple provenance (source_drawer_id). Per-drawer mode unaffected (keyed by own drawer id). Self-healing: one clean run records stable keys, then skips forever.

**2. "Why mining?" — mining was NOT re-running.** `project_sync_runs.summary.files_filed_this_cycle=0`. The mempalace miner skips unchanged files via `file_already_mined(collection, source_file, check_mtime=True)` (palace.py): skips when stored source_mtime≈current AND normalize_version current. The wasted ~141s/cycle was ALL KG, not mining.

**3. "Why indexing took 2 min with no changes?" — per-file skip cost.** `_mine_batched` (server_daemons.py) calls `mp_miner.mine(files=batch)`; mine() calls `file_already_mined()` PER FILE, each a paginated `collection.get(where={source_file})` against Qdrant. ~200 files × per-file query = ~2 min no-op. FIX v9.189.2 = BULK pre-filter in `_mine_batched`: `bulk_check_mined(col)` once → `{source_file: mtime}` map → drop files whose mtime matches → only changed files reach mine(); empty → mine() never called → returns 0. CAVEAT: mtime-only, so skips the rare normalize_version-upgrade re-mine (self-corrects on next edit / Full-Resync). bulk_check_mined + get_collection already in mempalace.palace.

**4. Scaling (v9.189.3, VERIFIED): fast project-level no-change gate.** Hundreds of projects × 6h resync → an unchanged sync must be ~free. Added `_project_source_fingerprint()` (server_daemons.py ~line 100): pure os.stat walk over ingested/+input_folders+web-urls/, sha1 of sorted path|mtime_ns|size. Gate at top of per-project loop (after web-URL sync, before start_run): if fp == stored sync_status.source_fingerprint AND state=='idle' → skip ALL phases, persist quick idle row + no-op run (skipped_unchanged=true), continue. fp stored on normal completion in sync_row. SUCCESS state is 'idle' not 'ok'. VERIFIED: run 3311 unchanged sync = elapsed 0.0s skipped_unchanged=1 (vs 285s full). Open scaling TODO (HANDOVER_SYNC_OPTIMIZATION.md): bulk_check_mined scans WHOLE shared collection per changed project (wing-scope it); closet regen rebuilds whole wing if any file changed (per-file scope).
