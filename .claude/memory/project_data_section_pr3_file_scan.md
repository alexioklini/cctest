**Shipped 2026-05-12** (PR3, on PR1+PR2 — see `project_data_section_pr1_phase_a_skeleton.md`, `project_data_section_pr2_anonymise.md`). Scope: §17 file-level GDPR scan for **tabular sources** — scans the workbench's DuckDB tables. docx/pptx/pdf file-scanning lands with the PR4 format arms; project-input-folder scanning + the path-traversal guard for arbitrary paths is deferred (PR3 scans workbench tables only).

**Design note (why tables, not files-on-disk):** the §17 plan says "scan a set of files". For PR3 I scan the **DuckDB tables** derived from uploads — that's what's actually queryable, and it makes the auto-fix → table mapping trivial (`data_anonymise` takes a `table`). A file → multiple tables (xlsx sheets) is handled because each sheet is already its own table. The "which files leak" framing maps cleanly to "which tables leak" for tabular sources.

**What landed (files):**
- `engine/tools/data_viz.py` — `tool_data_scan_files(args)`: `args.tables` (optional list) → scan those; omit → scan every table in the workbench. Per table, `_scan_table` runs `brain._pii_scan_text` over a 500-row sampled prefix of each column → findings grouped by `(column, category)` with `count` + ≤2 examples + `suggested_strategy` (from `_SUGGEST_STRATEGY`: contact/secrets/network→redact, financial→hash, personal/national_id/national_id_ctx/bare_id→tokenise; default tokenise). `worst_category` = the category with the most hits (severity-tiebroken). Returns `{files: [{name, type:"table", status: clean|dirty|error, findings, worst_category, total_hits}], summary: {scanned, clean, dirty, error}}`. **Modifies nothing.** Pure code, no LLM. Audit line `files_scanned`. (Connection opened read-only.)
- `brain.py` — registered `data_scan_files` (4 sites; `data_viz` group now `{data_query, data_anonymise, data_scan_files}`).
- `handlers/data_viz.py` — `POST /v1/data/sessions/<sid>/scan` — thin no-LLM call into `tool_data_scan_files` (`body.tables` optional). Primes/clears the `engine._thread_local` workbench context like the anonymise endpoints.
- `server.py` — route for `…/scan` (POST).
- `web/index.html` + `web/css/main.css` + `web/js/data.js` — "Scan for GDPR…" button in the Data view's chat-CTA panel; `dv-scan-modal` (§17 triage): summary bar (N clean / N dirty / N error), per-table row — clean rows dimmed, dirty rows show `worst: <cat> · N hits · suggested: <col> (<cat> ×N → <strategy>), …` plus **Auto-fix** (builds `columns[]` from findings via `_dvColumnsFromFindings` — one spec per column, most-severe suggested strategy wins; calls `…/anonymise` with `output_format=csv, embed_salt=true`; shows whether the rescan came back clean; marks the row `✓ fixed → <new_table>`) and **Fix in GUI…** (closes the triage modal, opens `dvOpenAnonModal(table)` pre-loaded). Footer: "Re-scan" + "Auto-fix all dirty" (sequential — each writes a new table — then re-scans). `dvScanState.results` holds the last scan.
- `CLAUDE.md` — Data Workbench section extended with `data_scan_files`.

**Smoke-tested 2026-05-12 (HTTP):** workbench with two tables — `scan_a` (customer/iban/amount; `iban` flagged since `financial`=warn in this deployment's config) + `scan_b` (clean) → scan → `scan_a` dirty with `suggested_strategy: hash` for the `financial` column, `scan_b` clean, summary {scanned:2, clean:1, dirty:1} → auto-fix `scan_a` with `iban→hash, embed_salt=true` → `scan_a_anon`, residual scan clean → re-scan → `scan_a` still dirty (original never mutated), `scan_a_anon` clean, `scan_b` clean.
